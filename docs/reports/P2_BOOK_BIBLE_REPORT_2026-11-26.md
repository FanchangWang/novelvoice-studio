## 2. 处理链

### 2.1 分遍与窗口

1. 每章先取已有摘要；没有摘要时生成并落库，供后续复用。
2. 按段落边界把章节切成窗口，单个窗口不超过配置的章节上限，避免截断段落。
3. 每个窗口携带已知角色注册表、本章摘要、上一章摘要，执行 P1 角色/关系/时间线观察。
4. 确定性聚类先按标准名与别名合并；别名同时指向多个角色时保留疑点，不强行合并。
5. 候选角色按每批 20 个交给 LLM 做全局归并、层级判断和人物弧整理。
6. 用全部章节的摘要与时间提示综合剧情时间线；超长时按章节顺序回退并记录异常。
7. 所有观察、关系、时间线写回 `book_bibles.content_json`，旧版本与角色弧不删除。

### 2.2 默认接受与异常

- 高置信结果自动通过，不要求逐角色确认。
- 以下情况进入 `review_items`：
  - 别名指向多个角色；
  - 候选角色可能对应多个已有角色；
  - 高层级角色置信度偏低；
  - 时间线综合失败；
  - 未识别到角色；
  - LLM 归并或时间线疑点。
- 只有 `blocking` / `warning` 会把圣经状态置为 `needs_review`；`info` 不阻塞。
- 新版本成功启用后，旧版本自身未解决的 AI 疑点自动标记 `ignored`，避免重复计数。
- 用户锁定字段在重跑时保留；AI 自动结果不产生锁定。
- 确定性清理：含“的”、较长且带亲属/身份词、或与其他角色正式名相同的别称不会进入别名；
  英文关系类型（如 `sibling`、`acquaintance`）在落库前归一到提示词约定的中文选项。

### 2.3 人物弧与时间线

- 人物弧按 `age_stage` 分组；LLM 给出阶段时使用 LLM 的章节范围，否则按观察确定性分组。
- 剧情顺序与章节顺序分离；倒叙、回忆、梦境不会被当作当前时间。
- 时间线统一重排为 1..N，避免模型给出重复或跳号。

### 2.4 全书概览

- 全书概览不再交给 4B 模型自由生成，而是只依据结构化角色表确定性拼装：
  章数、角色数、主要角色及其阶段。
- 概览不补充原文没有的亲属关系、死亡、失踪原因等情节；不确定内容留在人物表、
  关系证据和异常收件箱中由人工判断。

## 3. 选定章节重跑

接口支持可选 `chapter_ids`：

- 不传或传空：全书重跑。
- 传部分章节：只重新提取这些章节；其余章节从当前有效圣经的章节观察和时间线复用。
- 第一次生成没有有效基线时，部分重跑返回 422 `bible_base_missing`。
- 重跑生成新版本，旧有效版本变为 `superseded`；新版本自动成为有效版本。
- 复用章节数与实际分析章节数写入 `stats` 和任务结果。
- 章节级观察、关系观察和时间线都会持久化，因此中途失败也不会丢失已复用结果。

## 4. API

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/books/{book_id}/bible/analysis` | 启动全书或选定章节生成；可带 `{"chapter_ids": [...]}` |
| `GET` | `/api/v1/books/{book_id}/bible/status` | 任务、版本、有效圣经与开放疑点数量 |
| `GET` | `/api/v1/books/{book_id}/bible` | 当前有效圣经、角色、人物弧、关系、时间线与疑点 |
| `POST` | `/api/v1/books/{book_id}/bible/analysis/cancel` | 取消当前任务并恢复有效版本状态 |

`GET /bible` 只返回当前有效版本书籍范围内的角色疑点和角色之间的关系；
旧版本或已被新版本替换的角色不会混入响应。

## 5. 验证

### 5.1 自动化测试

- 后端全量：**126 passed**。
- P2 专项：**8 passed**，覆盖：
  - Mock 全书链：4 章、多窗口、角色、人物弧、非线性时间线、自动接受；
  - 第二次全量重跑：版本 2、旧版本 superseded、锁定字段保留；
  - 选定单章重跑：只调用目标章节、复用 3 章、时间线仍覆盖全书、旧版本失效；
  - 没有基线时部分重跑返回 422；
  - 中断恢复：任务与圣经标为 failed，书籍状态可见；
  - 别名冲突进入异常收件箱、关系正确序列化；
  - 同一角色按年龄阶段生成两条人物弧；
  - 描述性别称与角色正式名不会被当作别名，英文关系类型落库前归一到中文。

### 5.2 真实本机 Ollama 验收

使用 `tests/fixtures/sample_novel.txt`（4 章，约 1900 字节）与
`modelscope.cn/unsloth/Qwen3.5-4B-GGUF:latest`，最终一轮结果：

- 任务完成，耗时约 66 秒；
- 识别 4 个角色、8 条人物弧、4 条关系；
- 别名只保留“老沈”“小棠”；描述性的“林见秋姐姐”“旧书店老板”等未进入别名；
- 关系类型输出中文（亲属、旧识、姐妹、其他具体关系）；
- 全书概览为确定性生成，只列角色、层级与阶段，没有编造亲属或死亡情节；
- 时间线 4 章顺序完整；
- 4 条 `info` 疑点，不阻塞自动接受，书籍状态 `approved`。

样本本身对“阿棠是姐姐还是妹妹”存在前后矛盾，4B 模型也会在不同章节给出
“young_adult / adult”“unknown / adult”等阶段波动；这些会进入异常收件箱，
概览按结构化结果保守表述，不当作已人工确认的事实。

真实非线性时间线目前由 Mock 专项测试覆盖；真实长文本的倒叙质量仍需在 P3 验收中
用成长的测试文本继续观察。P2 不会自动下载或切换更强模型。

## 6. 已知限制

- P2 只有后端与 API，制作台 UI 尚未接入，按计划在 P6 统一实现。
- 4B 模型对亲属称谓、跨章事件和年龄阶段仍有波动；系统用证据、疑点和确定性合并降低影响，
  但不自动裁决亲属称谓矛盾，也不宣称全局概览已人工确认。
- 关系方向与语义仍由模型判断；反向且类型一致的重复关系会合并，冲突则保留证据等待人工处理。
- 时间线综合上限为 120 章 / 9000 字摘要材料；超限按章节顺序回退并进入异常。
- 人物同名不同人仍可能需要人工在异常收件箱拆开；系统不会凭猜测强制合并。
