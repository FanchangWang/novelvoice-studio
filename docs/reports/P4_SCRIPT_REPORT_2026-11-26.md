## 1. 结论

P4 后端已打通：基于当前有效分场、场景角色状态与角色圣经，逐场景分块生成有声剧本。
模型返回有序的原文引用，后端按绝对偏移精确对齐；未被引用覆盖的非空白原文由后端
确定性补齐为 `source=system` 单元，不静默丢字。剧本单元区分旁白、对白、内心独白、
音效、环境与停顿，cue 类单元不进入 TTS。每次生成产生新版本，旧版本与旧单元保留，
支持审核通过和版本回退。

实现遵守既有边界：真实 LLM 只走 `127.0.0.1` 的 Ollama；小说原文只读；音频与模型文件
不进入 SQLite；不自动下载模型、不调用云服务。P4 不生成音频，音效只做剧本标记。

## 2. 处理链

### 2.1 前置条件与任务

启动本章剧本前校验：

- 书籍存在且未删除，章节存在；
- 存在当前有效分场版本，否则 422 `scenes_required`；
- 本章没有处于 `pending/running` 的剧本任务，否则 409 `script_analysis_running`；
- 改编级别只接受 `light` / `standard` / `strong`，默认 `light`。

任务类型 `chapter_script`，阶段 `script`，沿用 `GenerationJob` 的进度、取消与启动恢复。
`total_items` 为分块数，进度随分块完成递增。

### 2.2 场景分块与提示

1. 只读取当前有效分场版本的场景，场景原文范围裁剪到章节范围内；
2. 单场景过长时优先在句末标点切分，仍超长才硬切，保证每次 LLM 调用有界；
3. 每块携带场景元数据（地点、时间、气氛、POV、摘要）、章节摘要、角色注册表、
   出场角色状态与改编级别；
4. 提示要求模型按原文顺序返回连续引用，不得改写原文引用本身；对白说话人只能来自
   已注册角色；音效、环境、停顿输出为 cue，不生成可朗读文本；
5. 模型可用于剧本改编的文本是 `text`/`display_text` 等表演字段，`source_text` 始终是
   原文锚点，二者分离。

### 2.3 原文对齐与确定性补齐

- 后端从上一单元结束位置向后查找模型给出的 `source_text`；
- 只在原文中找到精确引用时才接受该单元；找不到时不猜测、不模糊匹配；
- 相邻引用之间未覆盖的非空白原文按句子切分为系统单元：
  - `source=system`，置信度 0.2，`review_status=needs_review`；
  - 证据记录模型未覆盖、按原文补齐；
  - 系统单元仍参与原文顺序与偏移校验。
- 全部引用均无法对齐的分块按原文确定性切分回退，并记录 `script_llm_fallback`；
- 所有分块都失败时任务失败，不伪造一个空剧本版本。

因此剧本的 `source_start_offset`/`source_end_offset` 连续有序，覆盖章节原文中的
非空白内容；原文任何部分不会因为模型漏写而消失。

### 2.4 单元规范化

- 单元类型限定为 `narration` / `dialogue` / `inner_monologue` / `sfx` / `ambience` /
  `pause` / `unknown`；
- 旁白与内心独白的说话人类型为 `narrator`，对白映射到圣经中的标准角色；
- 说话人无法匹配时不猜测，保留快照姓名并生成 `script_unresolved_speaker`；
- 音效/环境/停顿的 `audio_status=not_applicable`；TTS 单元从 `none` 开始；
- 情绪、演绎、强度、语速、停顿毫秒数做白名单与范围收敛；
- 单元低于置信阈值时生成 `script_low_confidence`，不阻塞版本生成；
- 模型备注写入 `script_note:N` 疑点，保留可追溯信息。

### 2.5 版本、状态与恢复

- 每次成功生成创建新的 `script_versions` 与 `script_units`；
- 同一章只允许一个 `is_active=1` 的剧本版本；切换前先落库旧版本失效，避免部分唯一索引冲突；
- 新版本自动成为当前版本，旧版本、旧单元不删除；
- 有 warning/blocking 疑点时版本 `needs_review`，否则 `draft`；
- 章节 `script_status` 对应 `needs_review` / `completed`；
- 审核通过将版本置为 `approved`；回退只切换当前版本，不改变版本自身状态；
- 取消任务恢复旧版本状态；没有旧版本时回到 `not_started`；
- 启动时遗留的剧本任务标记为失败，章节恢复到旧版本或失败状态。

### 2.6 疑点编码

| 编码 | 级别 | 触发 |
|---|---|---|
| `script_llm_fallback` | warning | 某分块模型输出不可用，按原文确定性回退 |
| `script_source_fill` | warning | 模型引用未覆盖原文，后端补齐系统单元 |
| `script_unresolved_speaker` | warning | 对白说话人无法匹配角色圣经 |
| `script_low_confidence` | warning | 单元置信度低于阈值 |
| `script_note:N` | info | 模型返回备注 |
| `script_analysis_failed` | blocking | 任务整体失败 |

重跑成功后，本章旧版 AI 剧本疑点自动 `ignored`；仍存在的疑点按去重键更新。

## 3. API

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/chapters/{chapter_id}/script` | 启动本章剧本生成；202 返回任务 |
| `GET` | `/api/v1/chapters/{chapter_id}/script/status` | 任务、版本、章节状态与开放疑点数 |
| `GET` | `/api/v1/chapters/{chapter_id}/script` | 当前版本、单元与本章疑点 |
| `GET` | `/api/v1/chapters/{chapter_id}/script/versions` | 版本列表与单元数 |
| `POST` | `/api/v1/chapters/{chapter_id}/script/cancel` | 取消当前任务 |
| `POST` | `/api/v1/script-versions/{version_id}/approve` | 审核通过并设为当前版本 |
| `POST` | `/api/v1/script-versions/{version_id}/rollback` | 回退到指定版本 |

版本 ID 形如 `script_<16位十六进制>`。`GET /script` 在尚无版本时返回空单元和 `version=null`。

## 6. 已知限制

- **原文对齐只接受精确引用。** 模型改字、漏字或加入省略号都会对不上；后端不会模糊纠错，
  而是按原文补齐并标记。这样保证不丢原文，但可能产生较多系统单元和疑点。
- **补齐粒度是句子。** 未覆盖片段按句末标点切分；没有句末标点的长段可能成为一个较长系统单元。
- **章节标题会进入场景范围。** 如果分场把标题包含在场景内，模型未引用标题时会补一个系统旁白单元；
  这是当前“不丢原文”的直接结果。
- **分块独立调用。** 相邻分块之间没有跨块上下文合并，人物称谓和语气可能不连续。
- **音效只是标记。** P4 不生成、不混音音效；`sfx_json` 只描述标签、时机与强度。
- **没有单元编辑 API/UI。** 当前只支持整版生成、通过和回退，逐单元修改留给 P6。
- **真实模型质量未验收。** Mock 测试证明流程与约束，不证明 4B 改编自然度。
- **未绑定配音员。** `voice_cast_id` 在 P5 选角时写入；P4 单元保持空值。
