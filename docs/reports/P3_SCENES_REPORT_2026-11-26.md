## 2. 处理链

### 2.1 输入与窗口

1. 读取章节原文，校验章节偏移与源文本一致；不静默截断或修补原文。
2. 使用段落切分得到原文片段，并给每个片段分配连续 `index`。
3. 单段超过 `analysis.max_chapter_chars` 时，优先在句末标点切分；仍超长才硬切。
4. 按片段边界组装窗口，窗口不超过配置上限；分场任务的 `total_items` 即窗口数。
5. 每个窗口携带：当前有效角色圣经、人物弧、本章摘要、相邻章节摘要、本章剧情时间。
6. 本章剧情时间合并 P2 内容行与时间线概览：内容行缺少 `story_order` 等字段时，
   从 `timeline_json.chapters` 补齐，避免场景丢失全书剧情顺序。

### 2.2 结构化输出与覆盖校验

模型必须返回有序、连续、无重叠、无遗漏的场景列表。后端逐窗口校验：

- `paragraph_start/end` 必须落在窗口片段范围内；
- 第一个场景从窗口首片段开始，后续场景紧接上一场景；
- 最后一个场景覆盖到窗口末片段；
- 空结果、越界、跳号、重叠、遗漏均视为本窗口失败。

校验通过才写入 AI 场景。失败窗口按原文顺序整段回退为一个确定性场景：

- `source=system`，置信度 0.2；
- 状态只记录原文中出现的注册角色，`presence=mentioned`；
- 场景与状态都保留原文证据；
- 不丢弃原文，不阻塞其他窗口。

如果所有窗口都失败，任务整体失败并进入异常收件箱，而不是把空结果标成成功。

### 2.3 角色与状态

- 姓名只映射当前有效圣经中的标准姓名或已接受别名；无法匹配或别名歧义时不猜，
  跳过状态并生成 `scene_unknown_character`。
- 当前时间线（`time_mode=present`）的年龄阶段优先按人物弧校正；模型给出的阶段冲突时，
  以人物弧为准并生成 `scene_age_stage_conflict`。
- 倒叙、回忆、梦境、预叙场景不套用当前年龄，信任模型按剧情时间给出的状态。
- 状态字段按长度清洗；声音提示缺失时回退到人物弧声音提示或角色声音描述。
- POV 无法匹配时置空并生成 `scene_pov_unknown`（info，不阻塞）。
- 场景或任一状态低于 `analysis.scene_confidence_threshold`（默认 0.4）时，
  生成 `scene_low_confidence` 警告。

### 2.4 审核、版本与恢复

- 只有 `blocking` / `warning` 会把章节分场状态置为 `needs_review`；`info` 不阻塞。
- 重跑生成新版本：旧场景保留，章节 `scene_version` 指向新版本。
- 新版本成功后，该章旧版 AI 分场疑点自动 `ignored`；没有再次出现的疑点不会重复计数。
- 取消任务恢复旧版本状态；没有旧版本时回到 `not_started`。
- 失败时保留旧版本，写入 `scene_analysis_failed` blocking 疑点；没有旧版本时章节标记 `failed`。
- 启动时恢复中断任务：遗留 `chapter_scenes` 任务标记 `failed`，章节恢复旧版本状态或 `failed`。

## 3. API

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/v1/chapters/{chapter_id}/scenes` | 启动本章分场；返回 202 与任务 |
| `GET` | `/api/v1/chapters/{chapter_id}/scenes/status` | 任务、版本、状态与开放疑点数 |
| `GET` | `/api/v1/chapters/{chapter_id}/scenes` | 当前版本场景、角色状态与疑点 |
| `POST` | `/api/v1/chapters/{chapter_id}/scenes/cancel` | 取消当前分场任务 |

分场前置条件：

- 书籍存在且未删除；
- 存在有效角色圣经（`approved` 或 `needs_review`），否则 422 `bible_required`；
- 当前圣经时间线覆盖本章，否则 422 `bible_chapter_missing`；
- 本章没有正在运行的分场任务，否则 409 `scene_analysis_running`。

`GET /scenes` 只返回当前版本场景；开放疑点包含本章级疑点及本章任一分场版本的场景疑点。

## 4. 数据与控制

- 场景写入 `scenes`；角色状态写入 `scene_characters`；版本由 `chapter.scene_version` 指向。
- 任务类型 `chapter_scenes`，阶段 `scene`，沿用 `GenerationJob` 进度、取消与恢复语义。
- 阈值新增 `analysis.scene_confidence_threshold=0.4`；不改变既有片段/情绪阈值。
- 单窗口通常一次 LLM 调用；没有把整本书或全书角色状态塞入一次调用。
- 分场不修改小说原文、角色圣经、旧场景或旧音频。

| 章节 | 窗口 | 输出场景 | 角色状态 | 结果 |
|---|---:|---:|---|---|
| 第一章 雨夜来客 | 1 | 1 | 林见秋 / 沈砚 / 敲门者 | completed，2 条 info 备注 |
| 第二章 旧照片 | 1 | 1 | 阿棠 / 林见秋 / 沈砚（提及） | completed，无开放疑点 |
| 第三章 灯下 | 1 | 1 | 林见秋 / 沈砚 / 敲门者 | completed，2 条 info 备注 |

观察结果：

- 三章场景均完整覆盖原文片段，原文范围连续，无覆盖回退；
- 地点、POV、气氛、剧情时间与角色状态均落库；第一章 POV 识别为林见秋；
- 当前时间线年龄由人物弧校正，例如林见秋与沈砚为 adult、阿棠在旧照片场景为 teenager；
- 模型置信度多处给到 1.0，第三章场景为 0.9、状态为 0.8–0.95，均未触发低置信疑点；
  这种高置信度带有 4B 模型的过度自信成分，不应视为人工确认；
- 真实模型把三章都切成单场景，未在真实样本上展示多地点/多事件切分能力。

## 6. 已知限制

- **真实多场景切分尚未验证。** 4B 模型在本次样本中倾向单场景；多场景覆盖由 Mock 与受控 Provider
  测试证明，真实多场景质量需用更长、地点/时间变化更明显的文本继续评估。
- **置信度偏高。** 真实输出常为 1.0，低置信阈值不一定能筛出可疑状态；人工抽查仍必要。
- **回退粒度是窗口。** 一个窗口输出不合法会整窗回退，不会保留窗口中部分合法场景；这是为了
  保证顺序与覆盖不出现静默缺口。
- **状态证据可回退到场景级。** 模型未给状态证据时，会复用场景证据并标注为场景原文范围，
  不是状态级精确引用。
- **P3 只有后端与 API。** 分场查看、状态编辑、疑点处理 UI 尚未接入，按计划在 P6 统一实现。
- **角色未知与视角未知是不同强度。** 未知角色跳过状态并 warning；未知视角只置空并 info。
- **人物弧校正依赖 P2 时间线。** P2 对亲属、阶段和剧情顺序仍有波动，P3 继承这些限制。
- 取消/中断恢复不会伪造成功版本；旧版本和旧文件始终保留。
