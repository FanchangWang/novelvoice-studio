验收类型：阶段 4 开工前的功能轻度验收，不重新评审音质

> **目的：确认阶段 0–3 的真实链路已经足够稳定，可以作为阶段 4 的起点。**
>
> 本验收不重新听测全部音色，不重新给音质打分，不把“功能可用”写成“音质已验收”。
> 阶段 0 的人工听感结论、阶段 3B/3C 的音质结论继续沿用；本次只检查数据、流程、错误可见性和重启持久化。

## 1. 验收边界

### 1.1 本次必须通过

- 真实 Ollama 分析能产出可审核的角色、关系、片段。
- Qwen3-TTS + CosyVoice3 两个引擎服务能启动、生成、停止。
- 旁白和至少两个角色能绑定不同音色。
- 片段能生成 WAV、试听、重新生成、查看版本、回退版本。
- 修改台词或情绪后旧音频失效，重新生成成功。
- 停止引擎服务后生成明确失败，不伪装成功；重启后能恢复生成。
- 关闭并重启应用后，书籍、章节、角色、音色绑定、片段和音频版本仍在。

### 1.2 本次不要求

- 不重新评审音质、不重新评分 sad 表现力或句尾气声。
- 不验收批量生成、任务队列、连续播放器、M4B 导出（阶段 4–5 范围）。
- 不验收全书分析质量、长篇小说性能或长时间稳定性。
- 不把未完成的模型许可证核对算作通过；只记录状态。
- 不覆盖或改写既有阶段报告。

### 1.3 判定规则

- **通过（PASS）**：所有 P0 项通过，没有新的阶段 4 阻塞项。
- **有条件通过（CONDITIONAL PASS）**：P0 项通过，仅剩已记录的音质、许可证、体验优化或阶段 4 自身范围。可以进入阶段 4。
- **不通过（FAIL）**：任一 P0 项失败，或出现数据丢失、不可恢复的生成失败、伪装成功。修复后重新执行失败项。

P0 项未实际测试时记“未验证”，不能记“通过”。P1 项允许带条件通过，但必须写明影响。

## 3. 启动与停止顺序

### 3.1 启动

```powershell
# 1. 确认没有旧的 8775/8766/8767 监听；如有，先按项目脚本停止自己的进程
uv run novelvoice-studio worker status

# 2. 启动两个语音引擎服务（模型按需加载）
uv run novelvoice-studio worker start

# 3. 确认健康和实际 PID
uv run novelvoice-studio worker status

# 4. 启动应用（会打开 http://127.0.0.1:8775）
pwsh.exe -File scripts/start.ps1
```

如果引擎服务没有就绪，先看：

```powershell
uv run novelvoice-studio worker logs qwen_tts --lines 100
uv run novelvoice-studio worker logs cosyvoice --lines 100
```

### 3.2 停止

```powershell
pwsh.exe -File scripts/stop.ps1
uv run novelvoice-studio worker stop
```

验收结束后必须确认 8775、8766、8767 均无监听，并记录 `.run/workers/` 是否已清理状态文件。

## 4. 验收流程

建议顺序执行，每完成一项就在第 5 节验收单记录结果。预计 40–60 分钟。

### 阶段 0：模型与服务链路抽检

1. 打开 [阶段 0 POC 报告](../reports/POC_REPORT.md)，核对模型 ID、来源、硬件、运行命令和听感结论是否存在。
2. 打开 [模型清单](../MODELS.md)，核对 Qwen3-TTS、CosyVoice3、Ollama 模型的来源链接和缓存位置。
3. 访问两个引擎服务的 `/health`：

   ```powershell
   curl.exe http://127.0.0.1:8766/health
   curl.exe http://127.0.0.1:8767/health
   ```

   确认：
   - `ok=true`；
   - `model_dir_exists=true`；
   - Qwen 报告 CUDA 可用与 GPU 名称；
   - CosyVoice 报告 CUDA 可用与 GPU 名称。
4. 查看 [阶段 3 复听结果](../reports/STAGE3C_LISTENING_RESULT.md) 与 [阶段 3B 复听结果](../reports/STAGE3B_LISTENING_RESULT.md)，确认“有条件通过”与已知毛刺仍然被记录。
5. 记录许可证状态：`ttsfrd` / `wetext` 等核对仍未完成；这是阶段 5 前的待办，不作为阶段 4 开工阻塞项。

本阶段不重新生成三音色样本，也不重新听测阶段 0 的全部音频。

### 阶段 1：导入与持久化

1. 打开 `http://127.0.0.1:8775/library`，点击「导入 TXT」。
2. 选择 `tests/fixtures/sample_novel.txt`。
3. 在导入预览中确认：
   - 编码识别为 UTF-8（或高置信度编码）；
   - 章节结构与正文样例可见；
   - 前言和至少三章被识别；
   - 原文没有被截断。
4. 完成导入，打开书籍，确认章节列表和正文可读。
5. 记录自动生成的数据目录结构：`source/`、`parsed/`、`books/<book_id>/`。
6. 停止应用但保留引擎服务，重新启动应用；确认书籍、章节、正文仍在。
7. 可选：重命名一个章节；如果执行，确认不影响后续片段生成。

### 阶段 2：真实 Ollama 分析与人工审核

1. 在书籍工作区运行「全书分析」或按章节分析，至少覆盖包含三个角色的章节。
2. 记录分析任务是否有进度、是否能完成、失败时是否给出明确错误；不允许把超时或空结果显示为成功。
3. 在「角色关系」页确认：
   - 至少 3 个角色；
   - 至少一个别名（老沈 / 小棠 / 阿棠之一）；
   - 角色关系或章节摘要至少有一项可见。
4. 在「片段审核」页确认：
   - 有旁白、对白、内心独白等类型；
   - 说话人、情绪、演绎方式可编辑；
   - 低置信度或需要复核的片段有明确标记。
5. 修改一个片段的说话人或情绪，并确认字段被锁定；修改一个角色资料并锁定。
6. 对该章节重新分析一次，确认人工修改字段没有被覆盖。
7. 确认状态页或设置页显示本机 Ollama，而不是云端 LLM。

### 阶段 3：音色、生成与版本

1. 打开「声音库」，确认旁白和角色声音位来自当前书籍。
2. 为旁白、林见秋、沈砚分别设计音色：
   - 候选数量选 1；
   - 种子填 42（便于复现）；
   - 音色描述可沿用角色资料，或填写清晰的中文描述。
3. 逐个试听候选，并分别绑定为当前音色。三个 owner 必须使用不同音色。
4. 回到书籍工作区的「配音生成」页，至少生成：
   - 1 条旁白；
   - 林见秋的 1 条 neutral；
   - 林见秋的 1 条 sad 或 angry（可在片段编辑中修改情绪后生成）；
   - 沈砚的 1 条对白。
5. 检查每条生成结果的音频可播放、片段状态为 ready、说话人和音色显示正确。
6. 对同一条片段再次生成，确认出现 v002；打开「版本」，切回 v001，再切回 v002，确认当前版本和音频 URL 正确。
7. 修改该片段的台词或情绪，确认旧音频变为 stale/需要重新生成；重新生成成功，旧版本仍保留。
8. 停止 CosyVoice 引擎服务后再次生成，确认界面或 API 明确报错，片段状态为 failed，不产生伪造的 ready 音频。重新启动 CosyVoice 后生成成功。
9. 可在浏览器开发者工具确认音频请求返回 `audio/wav`，不是 JSON 错误伪装成音频。

### 重启、持久化与阶段 4 前置观察

1. 停止应用，重新启动应用；确认书籍、角色、音色绑定、片段、当前音频和版本历史仍存在。
2. 直接访问一个已生成片段的音频 URL，确认重启后仍可播放。
3. 记录当前阶段 4 边界：
   - 片段生成是同步 HTTP 请求，没有持久化 TTS 队列；
   - `generation_jobs` 目前由 AI 分析任务使用；
   - `playback_states` 表存在但未实现播放器；
   - 没有 WebSocket 进度接口；
   - `AudioService.generate()` 使用进程内 `_TTS_LOCK`，不是应用级队列调度器；
   - 进程在生成中被强杀时，`generating` 状态没有启动恢复逻辑。
4. 这些不是阶段 3 验收失败，而是阶段 4 必须实现的边界。发现额外阻塞时写入验收单。

## 7. 通过后的阶段 4 起点

阶段 4 不应从“再加一个生成按钮”开始，而应从以下边界开始：

1. 复用现有 `generation_jobs` 表，新增 TTS job 类型和状态语义，不创建第二套任务表。
2. 把同步 `AudioService.generate()` 拆成“创建任务”和“执行任务”，任务持久化后再调度。
3. 增加应用级单 GPU 调度器；不能只依赖 worker 内部锁或浏览器连接。
4. 启动时处理遗留的 `queued/generating` 状态，保证停止/重启后不永久卡住。
5. 生成前检查已有 current asset 与文本版本，避免重复生成。
6. 再接入 WebSocket/SSE 进度、取消、重试和播放器。

本验收单通过不等于音质、许可证或阶段 4 功能完成；这些仍需按各自阶段记录。
