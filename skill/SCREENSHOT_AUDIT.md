# 所提供截图的快速可读性诊断

根据用户提供的 1623×993 截图进行静态观察与像素颜色抽样。像素估算用于定位问题，不替代读取页面 CSS 后的正式 WCAG 对比度测试。

## 主要问题

1. **次级文字有低于 AA 的颜色组合。** 截图主背景约为 `#0A0B0D`。一组灰蓝色小字约为 `#626B78`，相对于该背景的估算对比度约为 `3.65:1`，普通字号低于 4.5:1。另一组约 `#818A97` 的文字约为 `5.64:1`，数值上达到普通文字 AA，但仍会受到字号偏小、字重偏细和实际显示尺寸影响。
2. **信息文字过于细小。** 侧栏说明、书籍元数据、章节/字数和日期等内容相对卡片及留白显得过小，长时间使用时阅读负担明显。
3. **层级依赖颜色过多。** 多处信息通过低亮度灰蓝色弱化，导致“次要”与“难以辨认”之间没有控制好。
4. **大面积暗背景和卡片的亮度差有限。** 主背景、卡片和侧栏都非常接近黑色，分区主要靠很弱的细线表达，内容边界不够明确。
5. **字体风格偏展示化。** 大标题可保留书卷气，但导航、正文、元数据和操作标签应优先采用清晰、笔画稳定的 UI 字体与常规字重。

## 修正方向

- 正文默认至少 16px，密集元数据至少 14px；避免 300 字重承担功能信息。
- 常用次级文字也维持至少 4.5:1；不要仅为了“高级暗色风”把文字降为低对比度。
- 拉开页面背景、内容表面、卡片和弹窗的层级；用适度表面亮度差与清晰边界替代几乎看不见的细线。
- 保留强调色作为操作/状态强调，不要让所有内容都使用低饱和蓝灰色。
- 必须同时提供浅色主题，且主题选择有“跟随系统 / 浅色 / 深色”三种模式。
